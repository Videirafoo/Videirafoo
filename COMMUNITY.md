# Comunidade Videirafoo

Este repositório é um espaço educacional aberto para estudantes e pessoas em início de carreira.

## Como participar

Você pode contribuir de várias formas:

1. **Testando o GitHub Student Dashboard** e enviando feedback.
2. **Relatando bugs reproduzíveis** com passos claros.
3. **Sugerindo melhorias** ligadas a um problema real.
4. **Melhorando explicações e documentação** para iniciantes.
5. **Corrigindo exemplos** quando houver erro verificável.
6. **Enviando pequenas melhorias de código**, preferencialmente acompanhadas de teste.

## Comece por aqui

Se esta é uma das suas primeiras contribuições open source, veja:

- [`CONTRIBUTING.md`](CONTRIBUTING.md) — fluxo de contribuição;
- [Issue #8 — good first issue](https://github.com/Videirafoo/Videirafoo/issues/8) — tarefa pequena de documentação da API;
- [template de Pull Request](.github/PULL_REQUEST_TEMPLATE.md) — checklist usado na revisão;
- [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md) — convivência;
- [`SECURITY.md`](SECURITY.md) — como lidar com questões de segurança.

A Issue #8 está propositalmente sem responsável para que uma pessoa iniciante possa assumir a tarefa e abrir um PR pequeno e verificável.

## Formulários

### Feedback do Dashboard

https://github.com/Videirafoo/Videirafoo/issues/new?template=dashboard-feedback.yml

Informe principalmente:

- se conseguiu concluir a análise;
- o que foi mais útil;
- onde ficou confuso;
- qual melhoria deveria vir primeiro.

### Relatar bug

https://github.com/Videirafoo/Videirafoo/issues/new?template=bug-report.yml

Um bom bug report contém comportamento observado, passos para reproduzir e resultado esperado.

### Sugerir melhoria

https://github.com/Videirafoo/Videirafoo/issues/new?template=feature-request.yml

A proposta deve começar pelo problema que precisa ser resolvido e, quando possível, trazer critérios objetivos de aceite.

## Segurança

Não publique em issues, PRs ou screenshots:

- tokens;
- chaves de API;
- senhas;
- arquivos `.env`;
- dados privados;
- vulnerabilidades sensíveis que ainda precisem de tratamento responsável.

Consulte [`SECURITY.md`](SECURITY.md) antes de publicar um problema de segurança.

## Princípios

- evidência antes de opinião;
- aprendizado antes de quantidade de commits;
- contribuições pequenas e revisáveis;
- nenhuma atividade artificial para aumentar métricas;
- respeito a licenças, autoria e regras de cada projeto externo;
- nenhuma contribuição é apresentada como conquista antes de existir evidência pública verificável.
