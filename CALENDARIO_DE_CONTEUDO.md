# Calendário de Conteúdo

Este calendário organiza a produção contínua de conteúdo educacional sem transformar o estudo em corrida por commits.

## Ciclo semanal sugerido

### 1. Fundamento
Publicar ou melhorar um conteúdo curto sobre um conceito:

- lógica;
- algoritmos;
- estruturas de dados;
- Git/GitHub;
- banco de dados;
- APIs;
- arquitetura;
- mobile;
- IA aplicada.

### 2. Prática
Criar um exercício ou pequeno desafio relacionado ao fundamento da semana.

### 3. Projeto
Evoluir um mini sistema com uma melhoria real: validação, persistência, testes, interface, API ou documentação.

### 4. Explicação
Registrar o que foi aprendido:

- problema;
- solução;
- decisões;
- erros encontrados;
- como testar;
- próximos passos.

### 5. Open source
Reservar uma etapa para contribuir em outro projeto:

- documentação;
- issue;
- teste;
- tradução;
- correção pequena;
- revisão.

## Ciclo mensal

Ao final de cada mês:

- revisar links quebrados;
- conferir versões e documentação oficial;
- atualizar exemplos desatualizados;
- escolher os melhores projetos do período;
- arquivar ou reorganizar conteúdo que ficou obsoleto;
- revisar README, roadmap e objetivos;
- registrar uma retrospectiva curta do que evoluiu.

## Tipos de conteúdo

Manter equilíbrio entre:

- **aprender** — notas e fundamentos;
- **praticar** — exercícios;
- **construir** — sistemas;
- **explicar** — documentação e tutoriais;
- **contribuir** — open source;
- **revisar** — atualização técnica.

## Critério de qualidade

Antes de publicar, verificar:

- outra pessoa consegue entender o objetivo?
- existe instrução clara para executar?
- o exemplo funciona?
- há indicação do nível de dificuldade?
- o conteúdo diferencia fundamento de detalhe dependente de versão?
- fontes oficiais foram verificadas quando necessário?
- o material ensina algo útil ou só aumenta atividade no perfil?

Se a última resposta for “só aumenta atividade”, não publicar como prioridade.
